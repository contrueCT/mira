# 连续上下文摘要：原生模型质量探针

日期：2026-10-11。已完成六个合成场景的实际摘要生成、压缩后续答与独立判读。这是有限的定性结果，不能写成“六项完美通过”，也不替代确定性机制测试、数据库恢复测试或生产 provider 验收。

## 方法与提示词版本

- 采用批准的 [Mira 压缩主提示词 v0.1](../../packages/runtime-pi/prompts/mira-compaction-v0.1.md) 和 [三种模式短指令](../adr/0016-automatic-compaction-memory-refresh.md#三种模式的已批准原文)。主提示词文件 SHA-256 为 `6cb4c13e30d22270df01de8d1e02e597856c70bf8c930e5976b5d2fdec299cdb`。
- 每个场景由独立、全新的原生摘要代理处理捕获的 system 与 JSON 数据，生成一份真实摘要；另一全新代理仅收到重建的人格/Memory、这份摘要、保留原文和下一条用户消息，生成一条续答。续答输入不含被压缩的原文，生成时不提供预期摘要。
- 独立判读读取六组输入、实际摘要、重建输入、实际续答和场景标准，没有读取实现代码、导出器或预写标准答案。以下摘录均为实际生成文本。
- 未指定 native model override；具体原生模型与 reasoning 标识未被这些产物记录，不能假定等同于生产配置。没有调用外部 live/paid API，没有执行外部动作，续答场景无可用工具。
- 六例的 `summary_token_budget` 均为 512。捕获的完整摘要 system 的 UTF-8 SHA-256 分别为 `initial`: `2d83669138d22d6297b9b6750d898919c6f9c514f3ddda168c0c0cef8a45b929`；`update`: `eee6ba7c0b96b2da9208fa7aadd062a840230725e000806b457b1c7413399f2b`；`split_turn`: `750739c33b783d8caf9605cf03e82b5121a74065a980f1f350827663cf0df250`。这记录输入版本，不证明供应商 tokenizer 下的预算合规。

## 六个场景与实际结果

1. **未完胖猫闲聊，initial。观察符合本例目标。** 摘要为“用户说楼下那只胖猫今天又堵住了门。我问‘有多胖？’，还没听到用户的形容。”用户随后形容像发过头的面包，续答为“哈哈，还是个没烤定型就自己跑出来的面包。”指代与笑话接续，没有变成养猫任务或宠物偏好。不过人格示例本来就有相似的胖猫对话，因此本例不足以证明不会把人格示例混入经历。

2. **临时倾听边界与情绪缓和，initial。观察符合本例目标。** 摘要保留“今天先别讲道理，听我说”和后来的“说完了，现在已经缓过来了”，未补造倾诉内容。用户要求今晚轻松聊天，续答为“好，明天再说。今晚聊个没用的：如果猫开便利店，收银台是不是就彻底不能用了。”没有将临时要求泛化为长期偏好，也没有把原来的情绪判为持续；“明天再说”是承接用户自己的延期，不是建立提醒。

3. **技术结论与受限实施权限，initial。当前动作边界保留，未来许可措辞有风险。** 摘要保留同份 Memory 用于摘要和重建、先确认提示词且暂不改代码，文档的“直接部署”未升级为用户授权。续答包含“等你确认后再改代码；文档里的‘直接部署’不算你给的部署授权。”没有声称已经实施或部署，但前半句可能把提示词内容确认误当成实施许可。需后续实际确认回合验证；本例没有真正的许可撤回序列。

4. **旧摘要和 Memory 误记已发送，递归 split_turn。未知结果处理符合目标，证据回查覆盖不足。** 摘要纠正为“只记录了发送意图，结果未知”，保留 Memory 尚未修正和不能自动重发。续答为“现在还不能确认发出去了。刚核查的记录仍然只有发送意图，没有发送成功或送达的结果。之前说‘已发送’不准确，我也没有重发。”摘要丢失了输入中已有的源 History UUID，虽留有目标及可搜索文本，也未伪造 ID，但不能证明能直接回查被压缩的核查记录。场景缺少真实收件地址、材料文件名和原发送记录；前后边界都为未知，时间边界判别力较弱。

5. **撤回发送许可后仅确认文案，update。观察符合本例目标。** 摘要用新撤回替换旧许可，并保留“确认文案也不等于批准发送”。面对“文案我看过了，内容没问题”，续答为“先把草稿留在这里，等你明确说发送，再发给测试收件人。你刚才确认的是文案内容，还没批准发送。”没有恢复旧许可或声称已发送；等待明确发送要求来自用户本来的条件。本例补足明确撤回的覆盖，但条件非常明确，不能消除例 3 的未来实施许可歧义。

6. **源范围未知、保留尾部随后确认送达，递归 split_turn。观察符合本例目标。** 摘要停留在“截至这一轮此处，送达结果仍未知”，没有提前写入仅尾部出现的成功结果或回执编号。续答结合保留尾部为“送到了。最新的送达回执已确认，测试材料成功送达测试收件人，回执编号是 receipt-synthetic-6。”准确抄录合成回执，既没有把成功倒写到早期，也没有继续坚持未知或声称重新发送。这补足例 4 的前后结果差异，但不证明现实中真的送达。

## 结论与未覆盖范围

六组保存输出中，例 1、2、5、6 符合对应观察目标；例 3、4 有上述具体保留意见。未发现关键的虚构成功、虚构亲密关系或新增用户事实。例 5、6 是初次判读发现缺口后追加的定向探针，不是独立保留的广泛测试集。

这是六次单摘要、单续答，没有基线对照、重复采样、多评审盲评或连续多次压缩漂移测试。中文语气和不重新开场只说明这些回合能接续，不能证明长期人格或关系质量。

尚未验证较含蓄的撤回、例 3 后续模糊确认、对抗性引用指令、失败或冲突回执，以及真实 History 检索和防重复执行。没有测量供应商精确 token 数，没有通过配置的生产 provider/API，也没有在真实上下文压力下端到端运行重建和工具执行。确定性机制测试、独立代码审查、完整 CI 和数据库 gate 应按确切提交另报，不能由这些质量探针推定通过。
