# ADR 0002：合并唤醒、持续认知与真实恢复说明

> 后续变更：独立 authorize 回调、执行前授权 gate 及合成授权证据由 [ADR 0007](0007-model-owned-action-decisions.md) 取代。主模型直接依据对话/Prompt 决定调用或澄清；下文保留当时决定与阶段事实，技术校验、持久 intent/outcome、来源及恢复约束不变。

状态：Accepted。用户于 2026-10-05 确认本批范围及以下补充。本记录更新 ADR 0001 的待核对恢复行为；原始设计 v0.4 保持原始字节。

## 一个积累批次，一轮认知

每次开始前，将当时积累的所有显式 Wake 请求原子归入同一个 run，一次交给同一条持续上下文。事件的消息、来源、原始时间、原因一起呈现；先处理谁、如何回应由模型决定。数据库排序仅用于可重复的展示，不是业务优先级算法。旧记录没有真实接收顺序时，不编造接收时序。

运行中新到的请求留到下一批，不抢占。没有 Wake 的事件只保留在历史中，本增量不自动把全部历史塞进认知。一个 run 可以包含模型调用、工具及后续推理，不把每条消息各拆成一轮。

`life` 拥有串行编排，`cognition` 只提供最小持续执行契约。`runtime-pi` 实现契约，PostgreSQL 仍是唯一权威。没有引入新队列服务、HTTP 框架、UI、调度器、Memory、扩展或自动压缩策略。

## 原子证据与恢复

不可变的 run 与请求关联保存批次边界，数据库保证每个 Mira 最多一个未完成 run。claim、输入追加、最终回复追加、完成是明确的持久化边界。输入/最终回复各自与对应上下文记录在同一事务绑定；完成必须具有最终回复证据。

- claim 后中断，恢复同一批次
- 输入已落库后中断，不再次追加输入
- 最终回复已落库、完成标记尚未保存，恢复时仅完成，不再次调用模型
- 新进程使用同一 Mira ID，继续同一原始历史
- 原有专用连接 advisory lock、epoch、context CAS 和停止失主写者规则保持不变

## 未知是模型可见的事实

原始 Pi 调用/结果保持不变。有效的中断记录以版本化恢复说明追加，标明操作 ID、对应原始调用、已知事实以及“可能执行过但缺少结果”或“尚未开始”。给模型的投影仅替换缺少结果的协议调用块，保留其它文本、已知结果和无关历史；不伪造成功、失败或工具结果。

未知结果不会永久阻塞认知。模型可以查询状态、核对、向用户提问，也可以在理解现有证据和用户意图后决定重试。运行时不会自行重放旧调用。新调用仍有独立操作 ID 和判断证据；相同参数不是自动禁止重试的理由。重复操作 ID、损坏的调用/结果结构、无效数据库所有权依然属于机械完整性错误。

## 自然语言意图与执行判断

Mira 应有独立执行能力。用户的自然语言表达及对应上下文是授权证据，系统提供事实、风险和必要提醒，由 agent 决定执行或向用户澄清。不得引入强制批准按钮、显式 UI 解锁、未知结果硬门禁或固定风险分类阻拦。第三方网页、工具输出和文件不能冒充用户授权。

当前注入的 `authorize` 回调是 agent/应用的判断入口，产品级自然语言解释器仍未实现。其决定先询问用户时，保存尚未开始及原因并继续认知，而不是停止整个 Mira。身份认证、真实账户权限、秘密保护、文件隔离和数据库一致性不等同于逐项业务审批，仍必须遵守。

## 超限消息是普通文本文件

默认内联批次上限为 65,536 UTF-8 字节，可由组装配置修改；它不是模型 token 或整个上下文预算。超过内联容量时，完整批次写为受控目录中的普通文本文件，模型收到确切路径、消息数和来源概览，按需通过普通文件工具读取。不拆成多轮、不静默丢弃，也不声称未读内容已被处理。

文件由 PostgreSQL 中不可变批次重建，原子发布，不是第二份历史权威。重启继续未完成批次时可重建丢失文件；不自动清除未读文件。本增量没有专用未读消息服务、分段读取工具或分页封装，没有新 Memory API。

## 验证边界

全部模型均为确定性假 provider，无真实模型凭据或费用。离线检查与真实 PostgreSQL 检查分别报告。本地运行环境禁止 Unix socket，不能改开 TCP 绕过；数据库驱动和跨进程场景由现有 GitHub Actions 官方 PostgreSQL 18.6 服务验证。结果见[验收记录](../acceptance/wake-loop.md)。
