# ADR 0010：Web 直接填写 API Key

状态：Accepted，2026-10-06。用户要求将网页“API Key 环境变量名”改成直接输入 API Key 并保存后端，存储参考 Pi。本决定取代 ADR 0009 的环境变量输入方式，不改变 CLI 的显式环境变量接口，不新增迁移、账户、多租户或公网部署。

## Pi 依据与本地存储

固定依赖 Pi 1.0.2 的 [AuthStorage](https://github.com/earendil-works/pi/blob/v1.0.2/packages/coding-agent/src/core/auth-storage.ts) 使用本地明文 `auth.json`，创建文件权限为 `0600`，创建目录为 `0700`，通过文件锁协调写入。它不是加密密钥库，其读取还支持命令/环境变量形式的配置值。

Mira 采用相同的本地明文加权限保护思路，复用已有私有 `MIRA_HOME/models.json` 原子替换与 revision CAS，同一 Mira 的跨进程单写者继续由 PostgreSQL fencing 保护；文件内的 CAS 串行化覆盖当前进程实例，不是任意外部程序共写的锁协议。一次提交私有模型配置、选择和密钥，避免把配置与密钥拆成两个文件后出现半次提交。公开 HTTP 数据与私有磁盘数据使用不同的严格结构。直接复用 Pi AuthStorage 会引入此处不需要的值解析、原地写入及缓存语义，因此不使用它，也不新增加密、主密钥、凭据数据库或密钥轮换系统。

文件必须在源码仓库外，新文件及替换文件为 `0600`；直接父目录和文件要求当前 UID 所有、无组/其他权限；已有宽松权限明确失败，不静默 chmod。目录、文件类型、链接与写入前 revision 均检查。读取畸形或不可安全访问的文件直接失败，不回退环境变量、不覆盖坏文件；诊断不包含原始 JSON 或 Key。备份应按秘密保管，不得放进源码 Git、Memory Git、数据库设置或日志。

## 输入与公开契约

- Web 使用密码式输入；GET/保存响应只给 `hasApiKey`，不返回原始 Key、掩码片段或长度
- PUT 的 `apiKey` 仅用于写入，缺省保留、非空字符串替换、`null` 清除；`hasApiKey` 只是读取状态，不能据此构造凭据
- 关闭/取消清除未保存输入；不写浏览器持久存储、URL、聊天消息或调试输出
- 自定义 Key 与连接 ID、服务地址、协议、发现地址绑定；改变目标不能带走已保存 Key，需重新输入
- 内置 Key 与服务商及其目录目标绑定；不能静默复用到不同服务商或被更改的目录目标
- 自定义发现可以使用未保存的本次输入，也可使用目标匹配的已保存 Key；发现不保存输入，失败不回显远端响应或 Key
- 保留既有 revision 冲突和运行中设置写入保护；成功保存后空闲边界生效，重启从同一私有文件恢复

密钥只由 server 在实际请求时解析并交给明确绑定的 transport。模型描述、Prompt、持久历史与正常 API 输出不携带密钥。既有 provider 错误清理、密钥回显拒绝、禁止重定向与无 ambient auth/header fallback 继续生效。清除密钥不删除对话或 Memory。

## 安全边界与验证

这是可信个人电脑上的本地单用户应用。权限并非加密；同一 OS 账户、管理员或该身份运行的普通文件/Shell 工具及扩展仍可访问凭据文件。本决定没有改变已经批准的宿主执行边界，也不宣称具备未知代码隔离。远程服务应使用 HTTPS；用户指定的 HTTP 服务不会加密传输 Key。

只使用合成 Key 与 mock provider 测试输入/保留/替换/清除、目标绑定、发现、重启、并发 revision、损坏存储、权限/链接错误与响应脱敏。PostgreSQL 恢复、Chromium 交互及最终提交的完整 CI 单独验证，不把离线测试当真实模型联通或付费调用验收。
