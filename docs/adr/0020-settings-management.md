# ADR 0020：设置窗口中的 Memory、扩展与运行记录

状态：Accepted，2026-10-13。用户确认管理能力，并要求主聊天界面维持现状；Memory 改为摘要与自然语言修改，ContextProvider 归属扩展（见 ADR 0019）。

## 界面与事实来源

沿用现有齿轮打开的设置窗口，内部提供模型、Memory、扩展、运行记录分区。主界面不增加按钮、工具卡片或导航。设置的关闭、Escape、浏览器返回、焦点恢复及未完成提交均保持可用，分区切换不悄悄丢弃编辑。

Memory 页读取当前磁盘 `MEMORY.md`，将它作为 Mira 已维护的高价值记忆总览安全渲染。它不是全部详细文件的模型摘要，不遍历自由组织的 Memory 来另造知识库，不额外调用模型，不维护第二份摘要事实源。内容 hash 仅标识这次只读展示，既不写入认知上下文，也不代表已提交 Git。空文件、未配置 Memory、读取失败和长内容明确呈现。

自然语言修改使用普通用户输入，明确表达修改记忆的意图，经既有消息幂等信封、Life Event、Wake、主模型及普通文件工具执行。不存在 Memory 写入 HTTP、文件目录编辑器或专用记忆工具。原用户请求与 Mira 回复仍进入同一持续聊天历史。

HTTP 接收成功只代表已提交。页面按原始消息身份查询它实际关联的 Wake，显示等待、进行中、结果未知或已完成，并展示该 Wake 的实际回复及 Memory checkpoint 回执。模型未修改、澄清或拒绝不能伪称记忆已改好。Git changed 仅说明该 Wake 的快照观察到差异，可能包括运行前或外部文件修改，不能充当逐行作者或请求因果证明。关闭页面不会取消已持久提交的请求，结果不明不自动重发。

页面读取磁盘与 runtime Memory 注入完全分离。初始化或成功压缩才读取并发布新冻结快照，重启恢复原持久快照；没有强制刷新、压缩、文件 watcher 或额外 Wake。

## 扩展管理

以现有 ExtensionHost 生命周期为唯一应用路径，显示实际启停状态、版本、能力及固定白名单错误说明。支持启停、重载、完整配置替换，以及选择已有暂存版本更新和已有历史版本回滚。配置不回填，用户输入仅提交给本机服务，关闭时清除；不把任意扩展配置、原始异常、路径或诊断直接传给浏览器。保存与激活是不同事实，配置已保存但运行失败必须如实显示。

管理写入在已有串行配置边界与认知空闲边界执行，使用版本核对防止旧页面覆盖新状态。重复点击被阻止；不确定响应先重读实际状态，不自动重复执行。无市场、代码编辑器、依赖安装器、硬授权审批或产品隔离沙箱。

## 按 Wake 查看记录

从现有持久 Wake、Event、Context、Tool 和 Memory receipt 关联查询，提供有界列表及详情。只投影触发来源/原因、真实模型标识、工具名称与结果状态、Memory commit/变更和已有安全诊断。原始参数/结果、thinking、system、任意异常及凭据不进入公开 DTO。

未持久化的模型失败或压缩失败没有可恢复历史，不补造日志、耗时、费用或历史模型配置。页面明确区分未记录与真实记录，当前临时错误不能归到无关的历史 Wake。没有第二套运行日志或语义 State。

## 验收边界

离线机制、HTTP 注入和 UI fixture 只证明各自覆盖面。新增独立真实浏览器 gate 必须经过生产 UI、HTTP、PostgreSQL、Wake/runtime、普通文件工具、Memory Git，并核对实际数据库/文件；仅模型响应可控合成。测试覆盖关闭/返回、重复点击、未完成请求、恢复、空态、窄屏以及敏感字段不泄漏。真实模型效果与上述确定性机制验收分别报告；通过状态只以确切提交实际执行结果为准。
