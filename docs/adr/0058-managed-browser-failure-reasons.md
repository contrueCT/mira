# ADR 0058：受管浏览器失败原因传递

状态：Accepted，2026-11-15。用户要求补齐服务器浏览器依赖，并修复启动失败原因被吞掉的问题，让 Mira 明确知道失败原因。

## 诊断和结果

保留受管 driver、manager、模型工具的现有分层。driver 将已知失败变为带可信实例标记的安全诊断，包含固定的阶段、原因、说明、执行状态和清理状态；manager 保留诊断和浏览器锁定；工具返回普通 `isError` 结果，让 Mira 在当前轮看到原因。未识别异常使用固定未知说明，不复制 Error.message、URL、页面、selector、输入、原生响应、stderr 或堆栈。

```text
驱动：依赖 / 版本 / 启动 / 导航 / 协议 / 所有权 / 清理
                 |
          固定白名单诊断
                 |
      manager 状态与 browser_list
                 |
      工具 isError → 当前 Mira 上下文
```

启动前确定失败（缺少 CLI、版本不符、显式 Chrome 路径不可用等）返回 `not_executed`，不占用一个结果未知的活跃浏览器槽。启动或命令已经发出后仍返回 `unknown` 并锁定原会话；浏览器 ID、失败阶段和清理结果可查，不重试、不换浏览器、不回放点击。数据库写入、运行时结果验证和 ownership fencing 的致命边界不改。

原生错误仅在内存中按固定标记归类 DNS、连接、TLS、超时、浏览器不可用、动态库/沙箱等问题；无法识别时只说明准确阶段和原因未知。清理失败不能覆盖原始失败阶段，须独立说明。正常成功路径、人工租约和 main/child 隔离不变。

## 运行依赖

仅在用户明确授权的服务器实例标准 `MIRA_HOME/tools/agent-browser` 安装固定 `agent-browser@0.39.1`，使用 `--ignore-scripts`，不运行 postinstall，不改全局 PATH。沿用已有系统 Chrome；不下载第二套 Chrome、不关闭 sandbox 或改变系统安全策略。当前服务下一次新建浏览器即可发现依赖；只通过普通受管驱动进行真实打开、snapshot 和 stream 验证。

代码通过草稿 PR、适用检查及全新独立审查后，再更新用户本次指定的 3213 服务。保留已部署的其他改动、数据、配置、凭据及扩展安装身份；依赖安装和代码更新分别报告实际验证结果。

## 验证

- Node 24 下浏览器定向测试 56/56 通过；覆盖安全分类、缺依赖/版本探测、原生 daemon 错误、所有权验证失败、清理保留原始错误、unknown 锁定与不重放。独立审查重复定向测试通过。
- 隔离 PostgreSQL 与真实运行时的 2/2 恢复测试通过：启动前拒绝和 daemon 启动失败都以 `isError` 持久保存，下一次合成模型请求收到具体诊断，同批后续工具可继续执行。未调用真实模型。
- 指定服务器安装固定版本后，用已有 Chrome 真实打开本机探测页、读取 snapshot、建立认证 stream 均通过；不代表外部任意网站或人工交还完整 E2E 已验收。
- 仓库完整检查的结果记录在对应 PR；服务器发布前备份既有私有目录、数据库和服务配置，并验证保留当前 General 设置与扩展安装身份。

- 合并前 CI 回归修正：保留原 `browser_open` 工具声明描述，错误阶段、原因和执行/清理状态由新工具结果直接提供。原生回复行为捕获及其 schema SHA 保持原样，继续执行完整声明一致性校验。
