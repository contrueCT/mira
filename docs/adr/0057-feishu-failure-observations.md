# ADR 0057：飞书失败原因进入 Mira 上下文

状态：Accepted scope，2026-11-15；已实现且本地验证通过，尚未合并或部署。用户要求检查飞书插件各种失败路径，避免吞掉原因，并在失败时告知 Mira。

## 处理规则

沿用普通扩展工具结果、入站 Event payload、ContextProvider 和设置状态。诊断只包含操作、固定原因、固定中文说明，以及有界数字 API 错误码和 HTTP 状态；不传平台错误原文、堆栈、URL、headers、令牌、凭据或完整响应。无法确认的原因明确标为未知，不推断成缺权限。

```text
SDK / 私有存储 / Host 失败
            |
       固定安全诊断
       /     |      \
工具结果  入站消息  插件上下文与设置
```

姓名查询失败仍投递原消息，附 `senderNameFailure`；1.5 秒超时与生命周期取消分开。搜索不完整保留具体诊断，按姓名发送把该诊断返回 Mira；不能把查询失败解释成收件人不匹配。发送的具体失败随分片回执保存，同 call ID 查询仍返回原诊断且不重新发送。已确认发送但网页同步失败，发送状态保持真实，并附独立同步诊断。

接收解析、收件箱写入、Host 发布、启动/注册/长连接故障通过有界的按操作诊断提供给 `feishu_status` 和 ContextProvider。后台故障在下一次自然模型请求可见，不新增轮询、额外 Wake 或告警重试；Host/数据库本身不可用时不能承诺立即通知模型。相关操作成功后清除相应当前故障，互不覆盖；冻结入站诊断和发送回执不改写。

官方 SDK 1.75.0 部分 WebSocket 错误只写日志。WSClient 单独使用 error 级别的安全日志适配器，按 SDK 固定前缀识别帧解码、分片合并、心跳响应和帧发送失败，经可选 `onDiagnostic` 回调提供观察；日志参数随即丢弃，不改变连接生命周期。其余 REST/EventDispatcher 日志仍静默。该适配与锁定 SDK 版本一同维护，升级时运行真实 SDK 的合成帧测试。凭据读取、保存、解绑删除失败也进入存储诊断。解绑中某一步失败时不追加重置原状态；凭据删除与状态保存仍是两个操作，修复时需核对实际凭据状态。

取消与正常忽略机器人/重复消息属于明确控制流。队列等待和清理中的 catch 只用于排空；原操作的异常仍交给调用方或当前诊断。收件箱、发送意图、去重、unknown 不重放及旧数据保留规则不变；不改权限、模型、服务器配置或生产部署。

## 验证

本地通过：Node 24.21.0 下 `TMPDIR=/private/tmp pnpm check`（后端/基础 1414 项、Web 98 项，类型、包边界和构建通过，无失败/跳过）；飞书六文件专项 103/103，独立复审重跑 103/103；隔离 PostgreSQL 的私聊/群聊恢复 2/2；真实 Edge/HTTP/PG/runtime 飞书浏览器门禁 1/1。

覆盖合成 HTTP/WS 的权限拒绝、限流、令牌、网络/TLS、超时、响应异常；真实官方 WSClient 的帧/分片/心跳/帧发送日志；Mira 入站/工具/上下文实际投影；诊断冻结、发送回执重启恢复和未知结果不重发；Host 投递失败和敏感内容排除。独立复审未发现阻断问题。上述外部传输及模型均为合成，未调用真实飞书账户或付费模型；尚未合并、部署或验收真实租户效果。

## 失败路径核对

| 路径 | 原行为与问题 | 处理后 Mira 可见内容 |
| --- | --- | --- |
| 用户姓名查询 | API 拒绝、异常、响应缺字段统一返回 null；超时被调用方吞掉 | 原消息附 senderNameFailure，区分权限、超时、网络、缺失姓名、未知原因 |
| 通讯录搜索 | HTTP 错误被压成通用异常；按姓名发送丢失搜索原因 | 不完整结果与发送工具保留同一安全诊断；不从部分结果自动选人 |
| 引用中的 user_id 校验 | 查不到用户容易表现为收件人不匹配 | recipient_lookup_failed，附真实查询失败；确认身份不同才返回 mismatch |
| 发送接口 | 只有 rejected/unknown 通用描述；同 call 重查无失败详情 | 保留真实结果不确定性，分片保存诊断并在重查/重启后返回 |
| 网页同步 | emitEvent 失败被 flush catch 吞掉，工具仍只有 sent | sent 保留，另带 publicationFailure；只恢复同步，不再发 HTTP |
| 接收消息 | 解析错误与落盘错误共用持久化失败提示；字段无效可被忽略 | 固定解析/冲突/落盘诊断，停止接收并提示核对缺失消息 |
| 不支持的媒体 | 只在预览文本显示通用占位 | 同一入站 payload 带 unsupported_message，不下载媒体 |
| 收件箱消费/Host 提交 | 后台 catch 只改设置状态 | 当前操作诊断进入 ContextProvider；原 pending 保留，重连恢复 |
| 启动/注册/连接 | 设置已有安全提示，模型观察不含错误；ready 后 start 拒绝可被忽略 | 模型可读安全提示及分类；ready 后的 SDK 拒绝也改变连接状态 |
| SQLite CAS/busy/文件保护 | 原存储层安全异常上抛，工具可能只收到通用宿主错误 | 操作诊断明确存储冲突、忙或不可用；旧证据与 CAS 保留 |
| SDK 内部帧/分片/心跳/发送 | 仅 logger.error，原 quietLogger 使故障完全不可见 | 只识别固定日志类别，提供安全观察；不复制日志、不把帧发送失败断言为业务发送失败 |
| 凭据读取/保存/解绑删除 | 失败可能只剩通用设置操作错误 | 存储诊断进入 Mira 上下文；不会在解绑失败时清空绑定 |

有意保留的 catch：首次文件不存在与并发 mkdir/EEXIST 属正常控制流；SQLite 回滚失败不能替换原事务异常；队列排空不替代原调用结果。通讯录 scope 接口被拒后，已有根部门路径会独立校验权限；根路径完整成功即为有效查询，根路径失败仍返回诊断。机器人、重复消息、退休连接、取消不会伪装成新业务故障。原始 SDK 日志不输出；回调、固定日志类别与 REST 结果使用安全诊断。
