# ADR 0050：NO_REPLY 静默与「已读」

状态：Accepted，2026-10-31。用户决定：只在最新一条用户消息下显示小字「已读」；不显示“Mira 读了，选择不回复”之类的提示或分隔线；不强制回复、不自动追问。

## 决定

### NO_REPLY

- 最终回复（`stopReason: stop`、不含工具调用）的全部文字去掉首尾空白后**恰好**是 `NO_REPLY` 时，聊天不显示它。记录照常留在上下文与 History，模型知道自己选择了静默。部分匹配、带标点、工具轮次中的同样文字都照常显示。
- 外部渠道（飞书等）只通过 `send_reply` 发送，最终回复从不自动外发，因此无需额外过滤。
- 系统提示 v0.4（`mira-system-v0.4.md`，section 仍为 `mira.system.v0.2`）：要静默就让最终回复恰好是 NO_REPLY；直接提问和进度询问必须真实回答。同时加入后台回执与运行状态段的说明（ADR 0049）。v0.3 字节保留为历史模板，旧快照照常校验。

### 「已读」

- 只计算时间线最新一页中最新的一条用户消息（`read: true`，HTTP 投影只在该条出现）。
- 条件：该消息已被某个 Wake 真正接收——作为批次输入（`wake_runs.input_record_id` 已写）或插话（`wake_live_inputs.input_record_id` 已写），含恢复后送达。与 Mira 是否回复无关。
- 余额暂停（ADR 0048）的 run 中的消息在暂停期间不算已读；用户发消息恢复后，新消息被接收即显示。
- 每次读取时计算，不进入不可变投影缓存。
- 前端：最新用户消息下右对齐小字「已读」；有正在发送的消息时不显示；扩展来源的消息不显示。

## 已知限制

- 「已读」只看最新一页；翻到更早历史不会显示旧消息的已读。
- 原生模型对 NO_REPLY 的实际使用尚未录制验证（未运行付费探针）。
