# ADR 0055：飞书连接诊断与群聊

状态：Accepted，2026-11-14。用户要求连接失败显示明确原因，并确认群内全部消息可唤醒 Mira、是否回复由 Mira 自行判断。本轮实现人类文字消息，不要求 @；继续忽略机器人消息，不下载媒体。

## 连接失败可见

沿用普通扩展设置的 `status.code/details`，不增加供应商 HTTP 路由或核心诊断接口。SDK 只传递固定原因及白名单权限名；插件将其转换为设置页的中文提示。覆盖未保存凭证、令牌获取被拒、机器人身份不可用、权限列表不可读、缺少具体权限、网络/TLS 失败、长连接超时及握手失败。

手动连接的预检失败、扫码后验证失败、重连和启动自动连接使用相同提示。成功后清除旧错误；取消不伪装为连接失败，不关闭未被替换的连接。未知错误保留通用提示，不公开平台原文、headers、URL、凭证、异常堆栈或任意上游权限名。

此前手动连接在保存应用绑定前失败，会只留下通用 operation=failed，没有插件状态详情；启动和扫码流程也会覆盖较具体的原因。本轮在插件内补齐这些路径，通用宿主继续只报告安全操作状态。

## 群消息与发送位置

```text
飞书推送人类私聊 / 群消息
        |
   持久收件箱 → ACK
        |
   冻结姓名与来源 → 同一个 Mira
                          |
                   决定观察或回复
                          |
                显式发送工具 → 原会话 / 明确目标
```

接收不筛选 @、关键词或“是否需要回复”。沿用一个持续 Mira、既有 Event/Wake、FIFO、持久去重和重启恢复。收到群消息本身不触发自动发送，也不赋予发送者主人权限。Mira 可观察后不调用发送工具，最终使用既有 `NO_REPLY`。

私聊 payload 不变。群消息在 `senderName/senderOpenId/messageId/text` 及可选引用之外，仅增加 `chatType: group` 和 `chatId`。不增加群成员列表、额外会话领域、群名搜索或新历史表。

`feishu_send_message` 增加 `chatId`，与姓名/用户 ID 互斥。单独引用群消息即回复原群；同时提供会话 ID 必须匹配。群引用与用户目标组合被拒绝，避免把私聊目标转换为群内发言。不同群之间的引用同样被拒绝。

现有私聊发送摘要和回执身份保持原样；只有显式 `chatId` 调用追加会话字段。解析后的群目标在执行前冻结，同 call ID 改群不能重新投递，unknown 不重放。沿用 SQLite schema 3 和旧私聊引用证据，不改写已冻结 Wake 或历史。

## 飞书后台配置

基础私聊/发送权限沿用 ADR 0054。群内全部用户消息需要应用身份权限 `im:message.group_msg`，机器人在群内，并配置长连接订阅 `im.message.receive_v1`。[接收消息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/events/receive)

新扫码注册请求声明基础权限和群消息权限。手动接入已有应用不修改后台授权或订阅。缺少群权限不阻断既有私聊连接：设置页提示无法确认完整群消息能力；只接收飞书实际推送的消息，不把收到少量 @ 消息称为已获取全部群消息。授予权限、可用范围及所需发布审批由用户/管理员完成。

## 验证边界

本地验证通过：`pnpm check`（后端/基础 1400 项、Web 98 项，无失败或跳过，含类型、边界与构建）；私聊/群聊 PostgreSQL 恢复 2/2；真实 Edge/HTTP/PG/runtime 浏览器门禁 1/1；全新独立复审无阻断。

离线测试覆盖安全错误投影、错误清除、取消、群内普通消息、多人/多群路由、跨群引用拒绝、群目标固定与重启去重。真实 PostgreSQL/浏览器门禁使用合成模型与飞书传输，验证设置页明确展示缺失权限，群消息进入模型后可选择 `NO_REPLY`，不会发送群消息，重启后不重复唤醒。真实租户群消息与模型判断质量需单独验收，不由合成测试证明。
