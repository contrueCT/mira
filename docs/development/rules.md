# 开发规则

## 工作节奏

- 先形成可核验的小增量，报告进展、阻碍和需要用户选择的事项
- 重要架构和工具链选择先确认，记录在 ADR；不要把未确认方案写成既定事实
- 每轮实现和每轮修复后，都由新的独立 `gpt-6.1-sol`、`max` 推理审查，且不继承实现对话
- 审查针对实际最终差异与验证证据；修复后重跑受影响检查，再开一轮独立审查
- 推送前展示结果并遵循确认的分支策略；默认草稿 PR。不得擅自合并、绕过保护或部署

## 代码与测试

- TypeScript monorepo，边界见 [architecture.md](../architecture.md)
- 显式公开 exports，检查直接和间接跨层依赖；SDK 不暴露内部数据库类型
- 核心契约避免绑定具体框架；仅在职责真实需要时增加抽象
- 早期开发只维护当前 v0.5/v0.2，不增加旧设计兼容、弃用提示或迁移层；当前持久上下文/历史、恢复/压缩与 Memory Git 数据完整性仍必须验证
- 先完成 Pi 恢复、工具边界与压缩可行性实验，再实现主循环
- 使用真实断言和可重复实验；不得通过假适配器或永远成功的 stub 宣称功能已实现
- 测试报告区分通过、失败、阻塞、未执行；模拟测试不等于真实服务联通
- 故障注入覆盖事务边界、进程重启、重复事件、并发写入及外部结果不明
- 对日期、时区、消息排序、重复去重和版本冲突使用明确测试
- 接口定型前保留待决策说明，不用未经确认的复杂类型锁死产品语义

## 数据与凭据

- 用户数据和服务凭据不进入源码仓库；环境示例只能包含占位符
- 日志和审查材料不输出 token、密码、认证配置或完整敏感用户数据
- 文件工作空间设置在仓库外，并为路径穿越、符号链接、权限和并发变更设计测试
- 文档中保存公开依赖版本及来源；不要复制本机认证文件

## 完成标准

最终差异通过适用的格式、类型、依赖、测试及构建检查，并完成独立审查。推送后核对远端确切提交与对应 CI；本地通过不等于远端已通过。没有真实实现的目录与流程必须标明尚未实现。

## 模型判断与机械边界

- 用户自然语言意图及上下文构成授权证据，系统辅助风险判断和提醒；不引入批准按钮、显式解锁或固定风险门禁
- 未知外部结果如实呈现给模型，允许认知继续查询、提问和作出有证据的新执行决定；不自动重放旧调用，也不把相同参数作为硬否决
- 真实身份认证、秘密保护、账户权限、跨进程所有权和上下文完整性仍是硬边界；第三方内容不能冒充用户意图
- 复用普通文件工具；超限输入存普通文本，不添加专用未读消息 API 或分页机制
