# @mira/web

React + Vite + 原生 CSS 的本地浏览器界面。只有一个持续 Mira 和单条 Timeline，没有会话列表、New Chat、账户或授权 UI。布局参考用户提供的白底、淡紫圆环、灰色 Mira 气泡与蓝色用户气泡。

## 命令

从仓库根运行：

- `pnpm --filter @mira/web build`：构建静态资源到 `apps/web/dist`
- `pnpm --filter @mira/web dev`：启动本地 Vite 开发界面，`/api` 代理到 `http://127.0.0.1:3210`
- `pnpm --filter @mira/web test`：发送信封恢复、历史去重与存储错误的确定性测试
- `pnpm check`：仓库聚合检查；浏览器交互另行验证

正式本地入口由 `apps/server` 的 Web 命令提供，静态界面与 API 同源。Vite preview 只用于查看构建产物，不提供持久服务。

## 行为与边界

- 页面刷新重新读取服务端历史。浏览器按 ID 合并最新页，按时间瞬间与细分精度排序；手动读取旧页保留可见消息位置；接近底部时才跟随新消息。断线后的不连续窗口显式提示补齐，长游标使用只读 POST 查询，不因隐藏记录空页重置翻页进度
- 页面可见时轮询，工作中约 1.2 秒、空闲约 5 秒；不展示未持久化 token streaming
- 每条提交先把完整 `{id,text,occurredAt}` 信封写入此标签页的 sessionStorage，再 POST；回执仅表示接收，不表示模型完成
- 中断或不明响应不会自动重发。刷新后保留原始 ID、文本与时间；用户明确点击“核对并重试”才读历史并使用相同信封重试；出现 `event:<UUID>` 后清除暂存
- 发送进行中禁用重复点击和 Enter；回执后可以继续发送待处理消息；中文输入法组合时 Enter 不发送
- Timeline 只渲染对话文本和必要通知，不显示工具活动、工具名称/状态、原始参数、结果、system prompt 或 thinking。`GET/POST /api/timeline` 仅返回 `items` 与 `nextCursor`，不读取或发送工具展示投影；内部执行和持久工具记录不变。文本使用 React 安全渲染与 `white-space: pre-wrap`
- 所有 API 请求包含 `X-Mira-Client: web`；不把 token 或密钥写入 HTML、URL、日志或浏览器存储
- 设置使用 `#settings` 与原生 dialog，支持关闭、Escape、浏览器前进/返回和焦点恢复；未保存编辑随关闭取消
- 设置和发现请求在关闭/切换后取消，迟到响应不会覆盖新编辑；保存有 revision 冲突提示，不静默覆盖
- 内置目录与自定义连接分开；自定义发现只提供候选 ID/名称，限额和能力须明确填写。界面直接接受密码式 API Key 输入，由本地后端保存；读取只返回已保存状态。留空保留、输入替换、显式清除后保存移除；目标改变不复用旧 Key
- 既有自定义连接与非当前模型会保留；未完成连接可单独取消，既有连接与密钥编辑可单独还原，保存前验证非当前编辑；不提供数据删除、历史重置或无后端功能的附件/语音按钮

## 验证重点

除构建与类型检查外，浏览器验收覆盖桌面/窄屏、空态/加载/错误、重复发送、响应丢失与刷新恢复、显式同 ID 重试、历史分页滚动、设置取消/前进/返回/迟到发现、revision 冲突、内置选择与手动自定义模型。所有模拟模型与 API fixture 验证不能作为真实模型联通证明。
